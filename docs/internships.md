# FDE internships

## What employers tend to expect

Intern postings generally look for a technical student with solid programming fundamentals, projects that show initiative, and the ability to work on real problems with a team. Customer exposure and production work can be substantial; the title does not guarantee a classroom-style placement.

### Common signals

- Enrollment in CS, engineering, or a related technical program (some postings accept equivalent portfolios)
- Evidence of building: class, research, personal, open-source, hardware, or startup projects
- One or more programming languages; exact stack varies
- Debugging, curiosity, clear communication, and comfort with ambiguity
- Interest in talking with customers and seeing work used outside a demo

## What stands out

- **Intern means applied work:** these examples include live customer deployments, production code, or real hardware—not only shadowing.
- **Projects matter:** employers explicitly accept class, personal, research, startup, and open-source work as evidence.
- **Customer communication is part of the job:** technical ability alone does not cover discovery, feedback, training, or deployment coordination.
- **The domain changes the stack:** AI/full-stack at Pace and CLAR AI; lower-level software and hardware at Revel and Saronic.
- **Check constraints:** location, in-person schedule, travel, graduation timing, language, and export-control eligibility are job-specific.
